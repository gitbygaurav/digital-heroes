# Digital Heroes — Decision Log

> Single source of truth for architectural and product decisions where the source brief was silent or ambiguous.
> Updated after each build phase.

| # | Ambiguity in brief | Decision | Reason |
|---|---|---|---|
| **D1** | "VAT-inclusive totals" but company is `.co.in` | Tax is configurable in `settings` (`label`, `rate %`, `inclusive` flag). Default: label `"GST"`, `18%`, `inclusive = true`. Tax portion is extracted (`tax = total - total / (1 + rate)`), never added on top. | Satisfies "VAT-inclusive, no surprises" while staying correct for any region. |
| **D2** | Currency not specified | Configurable `settings.currency`, default `INR`. All money stored as **integer minor units** (paise / pence). | Avoids float errors; data handling is graded on accuracy. |
| **D3** | "Stripe or equivalent" | Build a `PaymentProvider` interface. Implement **Stripe Checkout + webhook** first. Razorpay adapter is a documented stub. | Stripe may be restricted for some Indian accounts; interface keeps it swappable. |
| **D4** | Pipeline has `Quote` stage but pricing is instant (no quote forms) | `Quote` = an auto-created, saved priced configuration (a draft). It converts to `Order` on successful payment. Admin can also manually create a quote for a customer. | Keeps "no quote forms" while still honouring the pipeline. |
| **D5** | Where does a proof come from for upload-path orders? | Server generates a proof preview (PNG/PDF with print-area and bleed overlays) from the uploaded file as **v1**. | Same approval flow for both paths. |
| **D6** | When does the customer pay: before or after proof approval? | **Pay at checkout first**, then artwork/proof happens inside the order. Order moves `order -> artwork -> proof -> production`. Customer approves proof before production. | Matches the pipeline order given in the brief. |
| **D7** | Who creates the first proof version? | Auto-generated by the system when artwork is submitted (`v1`). Admin may upload a revised proof or regenerate (`v2...`) after a change request. | Every revision is logged. |
| **D8** | "Print-ready files unlock only once a proof is approved" | Enforced **server-side**: file-download endpoints check `order.proof_approved = true`. UI hiding is not enough. | Approval gate is a tested requirement. |
| **D9** | "Score / configuration of saved designs" (Section 10 module) | Interpreted as **"Scope / configuration"**: the saved design shows its configuration (product, size, material, quantity, template). No "score" is built. | Likely typo in the source brief. |
| **D10** | AI file format (`.ai`) uploads | Accept `.ai` (PDF-compatible), `.pdf`, `.svg`, `.png`. Treat `.ai` as PDF for preview. If preview fails, flag `"needs_review"` to admin. | Practical handling of AI files. |
| **D11** | Cart vs. single-item checkout | Support a simple **multi-item cart** (`order` has `order_items`). Each item has its own design and proof. | Corporate ordering later; simple to build now. |
| **D12** | Registration vs. guest checkout | Visitors can use the calculator freely. **Account required to design/order** ("Initiate signup / first order"). | Matches the role table. |
| **D13** | Email provider | **Resend** (with React Email templates). | Fast to set up, clean TypeScript templates. |
| **D14** | Designer library | **Fabric.js** in the browser; saved as a normalized **Scene JSON in millimetres**. Server renders from Scene JSON, not from the canvas. | Keeps rendering deterministic and server-side. |
| **D15** | Vercel serverless time limits | CSV merge runs as a **chunked job** (process N rows per invocation, resume via `csv_jobs` table). Output is zipped into Supabase Storage. | Avoids function timeouts on big race jobs. |
| **D16** | Admin creation | Admin role is set **only by SQL/seed or by another admin**. Signup always creates `customer`. | Prevents privilege escalation. |

## Phase Log
- **Phase 1 (Foundation & Auth):** Scaffolded Next.js 16 App Router with TypeScript `strict: true`, Tailwind CSS v4 ("Boutique Industrial" tokens), Supabase SSR + Admin clients, RLS-enforced identity schema (`accounts`, `profiles`, `settings`, `audit_log`), and role-guard middleware.
- **Phase 2 (Catalogue & Calculator):** Implemented parameter-driven catalogue schema (`0002_catalogue_pricing.sql`) and seed (`seed_catalogue.sql`) for all 6 divisions, pure shared pricing engine (`/src/lib/pricing/engine.ts`) with Vitest unit tests (tier boundaries 99/100/500, inclusive GST extraction, bounds checks), and public Product Hub (`/products`), Product Configurator (`/products/[slug]`), Standalone Calculator (`/calculator`), and filterable Gallery (`/gallery`).
- **Phase 3 (Cart, Checkout & Orders):** Added multi-item cart, server-authoritative checkout (`/api/checkout`) that recomputes every line item via `calculateProductPrice`, `PaymentProvider` interface with Stripe Checkout + idempotent webhook (`/api/webhooks/stripe`) and Razorpay stub, server-side `pdfkit` invoice generator (`/api/invoices/[orderId]`), and Resend email notifications logged to `email_log`.
- **Phase 4 (Web-to-Print Designer):** Built canonical Scene JSON schema in mm (`/src/lib/designer/scene.ts`), shared placeholder shrink-to-fit & tracking algorithm (`/src/lib/designer/fitting.ts`), print-area clamping (`/src/lib/designer/constraints.ts`), Fabric.js v6 in-browser editor (`/designer`), and finished artwork upload API (`/api/uploads` accepting `.pdf`, `.svg`, `.ai`, `.png` with `.ai` flagged `needs_review`).
- **Phase 5 (Proof & Approval Gate):** Added versioned proofs (`v1`, `v2`... marking prior versions `superseded`), immutable `proof_approvals` log (with IP and user-agent), `change_requests` workflow (`proof -> artwork`), customer `/proofs` review UI, email notifications (`proof_ready`, `changes_requested`, `proof_approved`), and server-side HTTP 403 approval gate on `/api/print-files/[orderId]`.
- **Phase 6 (Print-File & CSV Engine):** Built server-side SVG->PNG (`@resvg/resvg-js`) and vector PDF (`pdfkit` + `svg-to-pdfkit`) pipeline with bleed expansion and deterministic naming (`/src/lib/render/`), CSV validator (`papaparse`) with duplicate/empty/fitting checks (`/src/lib/csv/validate.ts`), chunked CSV merge + `archiver` ZIP packaging (`/src/lib/csv/merge.ts`), `/api/print-files/generate`, `/api/csv-merge`, and sample CSV (`/public/samples/race-numbers-sample.csv`).
- **Phase 7 (Customer Dashboard & Reorder):** Built all 6 Customer Dashboard modules (`/dashboard`), Order History with pipeline stage tracker (`/orders`), Saved Designs with configuration scope (`/designs`), Profile settings (`/account`, `/api/account/profile`), and one-click reorder (`/api/reorder`) with server-side repricing and optional quantity override.
- **Phase 8 (Admin Console):** Built Appendix B pipeline state machine (`/src/lib/pipeline/transitions.ts`) with Vitest coverage, searchable job database (`/api/admin/orders`, `/admin`), stage advancement with status history & customer emails (`/api/admin/orders/[orderId]/transition`), user role management (`/admin/users`, `/api/admin/users`), catalogue overview (`/admin/products`, `/api/admin/products`), and reports + Xero-ready CSV export (`/admin/reports`, `/api/admin/reports/xero`).
- **Phase 9 (Polish, Security & Ship):** Added HTTP security headers (`X-Frame-Options`, `X-Content-Type-Options`, `HSTS`, `Referrer-Policy`, `Permissions-Policy`) in `next.config.ts`, sliding-window rate limiting on `/api/uploads` and `/api/csv-merge`, global `error.tsx` & `not-found.tsx`, `prefers-reduced-motion` Framer Motion wrapper, Appendix A demo orders seed (`seed_orders_demo.sql`), and finalized `README.md`.
